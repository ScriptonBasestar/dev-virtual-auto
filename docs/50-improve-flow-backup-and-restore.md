# Improve Flow Backup and Restore

`am run dva-improve` 계열 플로우가 설정을 수정하기 전에 남기는 스냅샷의 위치·수명·복원
절차를 소유한다. 플로우 사용법은 [USAGE.md](../USAGE.md), 제품 범위는
[PRODUCT.md](../PRODUCT.md)가 소유하며 여기서 반복하지 않는다.

## 왜 스냅샷이 필요한가

git이 이미 히스토리를 갖고 있으므로 이 스냅샷은 두 번째 히스토리가 아니다. git이 덮지
못하는 창 하나를 덮는다 — **플로우 실행 시점의 미커밋 로컬 수정**이다.

| 상황 | 되돌리는 수단 |
| --- | --- |
| 마지막 커밋 상태로 되돌리기 | `git checkout -- dva.yml` |
| 커밋하지 않은 수정이 있는 상태에서 에이전트가 덮어씀 | **스냅샷만** |

두 번째 줄에서 `git checkout --`는 도움이 되지 않는다. 그 명령이 버리는 것이 바로
복구하려는 내용이기 때문이다.

## 어디에 남는가

```
<프로젝트>/backups/dva/
├── .gitignore                          # 내용은 "*" 한 줄
├── dva.yml.20260818-160000.bak
└── dva.yml.20260818-163000.bak
```

- **`tmp/`가 아니다.** `tmp/`는 "언제 지워도 안전하다"는 뜻이고 guided 스테이지의 실행
  리포트가 이미 거기 쌓인다. 스냅샷은 그 정리에서 살아남아야 하는 유일한 산출물이다.
- **`backups/dva/`로 네임스페이스를 둔다.** 프로젝트가 이미 `backups/`를 쓰고 있을 수
  있고, 아래의 마커가 그 내용을 git에서 숨겨버리기 때문이다. 하위 디렉토리로 내려두면
  영향 범위가 우리 서브트리에 갇힌다.
- **`.gitignore`가 자기 자신과 내용을 무시한다.** 그래서 대상 프로젝트의 루트
  `.gitignore`를 건드리지 않는다. 남의 저장소에 요청받지 않은 줄을 추가하지 않는다는
  뜻이다.

파일명은 `<설정파일명>.<YYYYmmdd-HHMMSS>.bak` 이다. 타임스탬프가 고정 폭이고 0으로
채워지므로 **사전순 정렬이 곧 시간순 정렬**이다. 아래 한 줄짜리 명령들이 성립하는
근거가 이 성질이다.

## 복원 절차

```bash
cd /path/to/project

# 1. 목록 확인 — 마지막 줄이 가장 최근
ls -1 backups/dva/*.bak

# 2. 복원
cp backups/dva/dva.yml.20260818-163000.bak dva.yml

# 3. 검증
dva validate
```

3번이 exit 0이면 복원된 설정을 DVA가 받아들인 것이다.

### 어느 스냅샷을 고르는가

**가장 최근 것이 항상 정답은 아니다.** 스냅샷은 각 실행 *직전*의 상태이므로:

- 플로우를 **한 번** 돌리고 결과가 나쁘면 → 가장 최근 스냅샷이 원하는 상태다.
  ```bash
  cp "$(ls -1 backups/dva/*.bak | tail -1)" dva.yml
  ```
- 플로우를 **여러 번** 돌린 뒤에야 손상을 발견했다면 → 가장 최근 스냅샷은 이미 앞선
  실행의 결과물을 담고 있다. 타임스탬프를 보고 마지막으로 정상이었다고 아는 시점보다
  **앞선** 것을 골라야 한다. 확신이 없으면 후보를 임시 파일로 꺼내 비교한다.
  ```bash
  diff backups/dva/dva.yml.20260818-160000.bak dva.yml
  ```

### 스냅샷이 덮지 않는 것

스냅샷은 **설정 파일 한 개**의 복사본이다. `20-transform` 스테이지가 수행하는 디렉토리
구조 이동처럼 파일 시스템을 바꾸는 변경은 되돌리지 않는다. 그런 변경의 복구 수단은
git이며, 그래서 플로우를 돌리기 전에 커밋해두는 것이 여전히 최선이다.

## 보존

**최신 10개만 남는다.** `prune_backups` 스텝이 스냅샷을 기록한 직후 초과분을 지우므로
디렉토리는 실행 횟수와 무관하게 10개에서 멈춘다. 이 디렉토리는 `*`를 담은 `.gitignore`를
들고 있어서 `git status`에 영원히 나타나지 않는다 — 무제한 누적이 문제인 이유가 바로
아무도 눈치채지 못한다는 점이었다.

정렬은 **파일명에 박힌 타임스탬프**를 기준으로 한다. `-t`(mtime)를 쓰지 않는 이유는
스냅샷을 다른 곳에서 복사해 왔을 때 mtime과 파일명이 어긋나기 때문이다. 그렇다고 이름
전체로 정렬해서도 안 된다 — `dva.yaml.*`이 `dva.yml.*`보다 앞서므로(`a` < `m`) 설정
파일명을 바꾼 프로젝트에서는 **최신 스냅샷이 먼저 지워진다**. 그래서 basename과 무관한
세 번째 필드만 본다.

```bash
# 스텝이 하는 일과 같다. 손으로 돌릴 때는 보존 개수만 바꾸면 된다
cd backups/dva
ls -1 | grep '\.bak$' | sort -t '.' -k 3 -r | tail -n +11
```

`ls`는 `-a` 없이는 `.gitignore`를 나열하지 않고 `grep`이 `.bak` 접미사를 한 번 더
요구하므로, 마커와 `.bak`이 아닌 파일은 정리 대상이 되지 않는다. 삭제 범위는 이
디렉토리 안으로 한정된다.

## 실행 디렉토리 요구사항

스냅샷은 플로우를 **대상 프로젝트 디렉토리에서 실행**할 때만 기록된다. 다른 경로를
`target`으로 넘기면 `check_run_dir` 가드가 첫 쓰기 이전에 멈춘다. 이유와 배경은
[USAGE.md의 "실행 디렉토리 요구사항"](../USAGE.md#실행-디렉토리-요구사항) 참조.

## 구현 위치

| 대상 | 스텝 |
| --- | --- |
| `agent-mesh-flows/dva-improve.yaml` | `backup_paths` → `backup_marker` → `backup_config` → `prune_backups` |
| `agent-mesh-flows/dva-improve-guided/30-configure.yaml` | 같은 4단계 |

두 경로 모두 설정이 이미 존재할 때만 동작한다. 새 프로젝트는 설정을 생성하므로 잃을
이전 상태가 없다.
