## What is DVA?

DVA is a Docker Compose / Kubernetes CLI wrapper. Instead of memorizing long `docker compose exec ...` commands,
you run short aliases defined in `dva.yml`.

## Rules

1. **Read SOUL.md first** — If SOUL.md exists, read it before making any architectural decisions.
2. **Always use DVA** — Never bypass DVA with raw `docker compose` or `kubectl` commands if DVA has a command for it.
3. **Discover first** — Run `dva ls` or `dva manifest -f json` to see available commands before guessing.
4. **Lifecycle via DVA** — Use `dva up`, `dva down`, `dva stop` for container lifecycle management.
5. **DVA handles env** — DVA automatically applies environment interpolation, overrides (`.sb/dva/*.yml`), and networking.

## Quick Reference

```bash
# Bootstrap (if dva.yml is missing)
dva init                            # Scaffold only when a Compose file is in this directory
am run dva-discover                 # Inspect Compose-less, non-standard, or multi-project layouts first

am run dva-improve -p mode=rewrite  # Explicit opt-in for a full rewrite

# Discover available commands
dva ls                 # List all commands
dva manifest -f json   # Machine-readable manifest

# Run commands
dva <command>          # Run an interaction command (e.g., dva shell, dva test)
dva run <command>      # Explicit run (same as above)

# Named lifecycle (replace PLAN with an exact name discovered above)
dva up PLAN            # Start the selected plan
dva stop PLAN          # Stop the same plan, keeping resources
dva down PLAN          # Tear down the same plan in reverse dependency order
dva build PLAN         # Build the named plan

# Health & Diagnostics
dva doctor             # Run checks (toolchain, files, docker)
dva status             # Show service health
dva config validate    # Validate dva.yml

# Debugging
dva config             # Show resolved configuration
dva run <cmd> --explain  # Show what a command would do without running it
```

## Configuration Structure

DVA configuration lives in:
- `dva.yml` — Main config (commands, compose files, environment)
- `.sb/dva/*.yml` — Modular config fragments (merged automatically)
- `dva.override.yml` — Local overrides (typically gitignored)
